# Project Brief: โมเดลทำนายผลบอลจากกฎราคาพูล/แฮนดิแคป/สูงต่ำ

> เอกสารนี้เขียนเพื่อส่งให้ AI ช่วยลงมือทำโปรเจกต์ต่อ ให้อ่านทั้งหมดก่อนเริ่มเขียนโค้ด

## 1. เป้าหมาย

สร้าง **โมเดล** ที่ทำนายผลบอลจากกฎในตารางของผมในรูป tip.jpg (ราคาแฮนดิแคปเปิดคู่กับราคาพูล, ราคาเสมอ HT/FT) โดยแต่ละนัดโมเดลเลือกตลาดที่จะทาย คือ

- **แฮนดิแคป (AH):** ทีมต่อชนะราคาหรือไม่
- **สูงต่ำ (O/U):** สกอร์รวมสูงกว่าเส้นหรือไม่

ถ้าไม่มีตลาดไหนมั่นใจเกินเกณฑ์ ให้ **ข้ามนัด** ไม่บังคับทาย

**ข้อบังคับจากอาจารย์:** ห้ามใช้ dataset สำเร็จรูป ต้องดึงข้อมูลเองด้วยโค้ดจาก API/เว็บ และเก็บหลักฐานการดึง (ข้อมูลดิบ + วันที่ดึง)


## 2. กฎในตาราง (สมมติฐานที่ต้องพิสูจน์ ไม่ใช่ความจริง)

ตารางต้นฉบับเป็นสูตรของคนทำนาย ถือเป็นสมมติฐาน ห้ามฮาร์ดโค้ดว่าถูกแน่ ให้วัดผลย้อนหลังและให้โมเดลเรียนรู้

### 2.1 ราคาพูล (1X2 ของทีมต่อ) คู่กับ AH ตอนเปิด

| AH เปิด (ทีมต่อ) | ราคาพูลทีมต่อ |
|---|---|
| -0.25 (ปป.) | 2.06 - 2.10 |
| -0.5 | 1.79 - 1.83 |
| -0.5 ไม่ไหลไป -0.75 (กฎพิเศษ แถวสีแดง) | 1.58 - 1.59 (ต่อ+สูง) |
| -0.75 | 1.60 - 1.64 |
| -1 | 1.47 - 1.50 |
| -1.25 | 1.30 - 1.33 |
| -1.5 | 1.27 - 1.29 |
| -1.75 | 1.18 - 1.20 |
| -2 | 1.15 - 1.18 |

### 2.2 กฎเกี่ยวกับประตู (ใช้ทำนายสูงต่ำได้โดยตรง)

- ราคาพูลเสมอ HT >= 2.35 → โอกาสมีสกอร์ HT สูง
- ราคาพูลเสมอ HT >= 2.45 → โอกาสมีสกอร์ HT ประมาณ 90% (ตามที่ตารางอ้าง ต้องพิสูจน์)
- ราคาพูลเสมอ FT = 4.30 +/- 0.05 → เกมเปิด ทีมต่อบุกใส่ ทีมรองมีโอกาสทำประตู

## 3. Feature ที่ควรสร้าง

```python
import pandas as pd, numpy as np

RULES = pd.DataFrame([
    (-0.25, 2.06, 2.10), (-0.50, 1.79, 1.83), (-0.75, 1.60, 1.64),
    (-1.00, 1.47, 1.50), (-1.25, 1.30, 1.33), (-1.50, 1.27, 1.29),
    (-1.75, 1.18, 1.20), (-2.00, 1.15, 1.18),
], columns=["ah", "pool_min", "pool_max"])

def rule_features(ah_open, pool_fav, tol=0.03):
    row = RULES[np.isclose(RULES.ah, ah_open)]
    if row.empty:
        return pd.Series({"rule_match": 0, "rule_near": 0, "rule_dist": np.nan})
    lo, hi = row.pool_min.iloc[0], row.pool_max.iloc[0]
    dist = 0 if lo <= pool_fav <= hi else min(abs(pool_fav - lo), abs(pool_fav - hi))
    return pd.Series({"rule_match": int(dist == 0),
                      "rule_near": int(dist <= tol),
                      "rule_dist": dist})

df["draw_ht_high"]  = (df.draw_ht_odds >= 2.35).astype(int)
df["draw_ht_vhigh"] = (df.draw_ht_odds >= 2.45).astype(int)
df["draw_ft_match"] = df.draw_ft_odds.between(4.25, 4.35).astype(int)
df["ah_abs"]        = df.ah_open.abs()
df["total_x_ah"]    = df.ou_line_open * df.ah_abs
```

Feature เพิ่มเติม: เส้นสูงต่ำเปิด, ราคาน้ำสูง/ต่ำ, ค่าเฉลี่ยประตูย้อนหลังของแต่ละทีม, อัตราทะลุเส้นสูงต่ำของนัดก่อน ๆ (**ต้อง `.shift(1)` เสมอ** ก่อนทำ rolling)

## 4. Label และการคิดผล

```python
def ah_result(goal_diff_fav, ah):
    """goal_diff_fav = ประตูทีมต่อ - ทีมรอง, ah เป็นลบ เช่น -0.75
    คืนกำไรต่อ 1 หน่วย (ยังไม่หักค่าน้ำ)"""
    x = goal_diff_fav + ah
    return 1.0 if x > 0.25 else 0.5 if x == 0.25 else 0 if x == 0 else -0.5 if x == -0.25 else -1.0

def ou_result(total_goals, line, side="over"):
    x = total_goals - line if side == "over" else line - total_goals
    if x >= 0.5:   return 1.0
    if x == 0.25:  return 0.5
    if x == 0:     return 0.0
    if x == -0.25: return -0.5
    return -1.0
```

ผลเจ๊า (เส้นเต็มลูกพอดี) ให้ตัดออกจาก label แบบ binary หรือนับแยก แต่ต้องรายงานให้ชัด

## 5. โครงโมเดลเดียว (multi-output)

- ใช้ multi-output เช่น `MultiOutputClassifier(LogisticRegression/XGBoost)` หรือ neural net สองหัว ให้ความน่าจะเป็นสองค่าพร้อมกัน: `p_fav_cover` และ `p_over`
- **กฎเลือกตลาดต่อนัด:** คำนวณ edge = ความน่าจะเป็นของโมเดล - ความน่าจะเป็นจากราคาน้ำ (ตัดค่าน้ำแล้ว) เลือกตลาดที่ edge สูงสุด ถ้า edge ต่ำกว่าเกณฑ์ที่ตั้งไว้ล่วงหน้า ให้ข้ามนัด
- เริ่มจากโมเดลง่าย (Logistic Regression) ก่อน ค่อยลอง XGBoost

## 6. แหล่งข้อมูล

### 6.1 ราคา (AH เปิด, 1X2 เปิด, เส้นสูงต่ำ, ราคาเสมอ HT): OddsPapi

- Base URL: `https://api.oddspapi.io/v4`
- Endpoint: `/odds`, `/historical-odds`, `/bookmakers`, `/markets`
- แผนฟรี **250 requests/เดือน** เข้าถึงเจ้ามือครบ และมีข้อมูลย้อนหลังระดับ tick พร้อม timestamp (ข้อมูลนี้มาจากบทความของ OddsPapi เอง ต้องยืนยันด้วยการเรียกจริง)
- Asian handicap มีหลาย market ID ต้องทำ mapping เอง
- แต่ละ fixture มี `externalProviders` (Betradar, Sofascore, Pinnacle) ใช้เป็น join key
- **ไม่มีผลแข่ง/สกอร์/สถิติ** ตามเอกสารของ OddsPapi (ต้องตรวจ response จริงว่ามีฟิลด์สกอร์ปนมาไหม)
- เจ้ามือที่แนะนำเป็นมาตรฐานอ้างอิง: Pinnacle (ต้องระบุในรายงาน)
- ตัวเลือกสำรอง: TheStatsAPI (มี AH เปิด + ข้อมูลย้อนหลัง 10 ปี ยังไม่ทราบแผนฟรี), The Odds API (ย้อนหลังกินเครดิต 10 เท่า)

### 6.2 ผลแข่ง (label): ต้องมีแหล่งแยก เพราะ OddsPapi ไม่มีสกอร์

ตัวเลือก (ผู้ใช้ตั้งใจจะใช้ API-Football ตอนโมเดลเสร็จ แต่ตอนเทรนต้องมีผลแข่ง ไม่งั้นไม่มี label):

1. **API-Football** (ฟรี 100 requests/วัน) คืนทั้งฤดูกาลใน 1 request ใช้โควตาน้อยมาก
2. **football-data.org** ฟรีสำหรับลีกหลัก
3. **Thscore** (https://www.thscore99.com/football/schedule/today) ดูหัวข้อ 6.3

### 6.3 Thscore: สถานะการสำรวจ

- หน้าเว็บโหลดข้อมูลแมตช์ด้วย JavaScript ผ่าน API ภายใน เนื้อหา HTML ดิบไม่มีรายการแมตช์ ใช้ `requests` + BeautifulSoup ตรง ๆ ไม่ได้
- วิธีดึง: (1) เปิด DevTools > Network > Fetch/XHR หา endpoint ที่คืน JSON แล้วเรียกตรง (2) ถ้าหาไม่เจอ ใช้ Playwright/Selenium
- **ย้อนหลังได้แค่ 7 วัน** (แถบวันที่ +/-7 วัน) ไม่พอสำหรับ backtest 100 นัด เว้นแต่มีหน้าผลย้อนหลังตามลีก/ฤดูกาล (ยังไม่ได้ตรวจ)
- ยังไม่ทราบว่าเว็บมี **ราคาเปิด** ไหม ถ้ามีแค่ราคาปัจจุบัน/ปิด กฎในตารางใช้ไม่ได้
- ยังไม่ได้อ่านข้อกำหนดการใช้งาน ให้เช็กหน้า disclaimer และ `/robots.txt` ใส่ delay ระหว่างคำขอ ไม่ยิงถี่
- เหมาะกับแผน B (เก็บรายวันไปข้างหน้า)

## 7. วิธีทดสอบ

### แผน A: Backtest (ทำก่อน)

- ดึงแมตช์ย้อนหลังประมาณ 100 นัดจากลีกเดียว เก็บลง SQLite ของตัวเอง
- **Train 80 นัด / Test 20 นัด แบ่งตามเวลา (เก่า→ใหม่) ห้ามสุ่ม**
- ซ่อนเฉลยด้วย `blind_view`:

```python
def blind_view(matches, as_of):
    known = matches[matches.date < as_of].copy()
    todo = matches[(matches.date >= as_of) &
                   (matches.date < as_of + pd.Timedelta(days=1))].copy()
    todo[["home_goals","away_goals","ht_home","ht_away"]] = None
    return known, todo
```

- Walk-forward: แต่ละวันโมเดลเห็นเฉพาะแมตช์ก่อนวันนั้น ทำนาย แล้วค่อยเฉลย
- เก็บ payload ดิบจาก API ลง DB (กันเสียโควตาซ้ำ + เป็นหลักฐานว่าดึงเอง):


### แผน B: Live forward test (ทำเมื่อ A ผ่านเกณฑ์)

- เก็บตารางแข่ง + ราคาล่วงหน้า ทำนาย บันทึกพร้อม timestamp แล้วเติมผลหลังแข่งจบ

- ตั้ง cron/GitHub Actions ให้รันอัตโนมัติ

### เกณฑ์ผ่าน (ตั้งก่อนดูผล)

- Log loss / Brier score ดีกว่า baseline จากราคาน้ำ (ตัดค่าน้ำแล้ว)
- กำไรสะสมหลังหักค่าน้ำเป็นบวก ไม่ได้มาจากไม่กี่นัด
- ผลคงที่หลายช่วงเวลา

## 8. ข้อควรระวัง

1. **Data leakage:** feature ทุกตัวต้องใช้เฉพาะข้อมูลที่รู้ก่อนเริ่มแข่ง ใช้ `.shift(1)` กับ rolling
2. **ราคาต้องเป็นราคาที่ได้จริง ณ เวลาทำนาย** ใช้ราคาปิดทำนายแต่เดิมพันราคาเปิดไม่ได้
3. **กฎใช้ราคาเปิด** ต้องมีราคาเปิดย้อนหลังจริง ๆ
4. **อย่าปรับช่วงกฎตามข้อมูล test** ล็อกกฎก่อนทดสอบ
5. **ตัวอย่างน้อยมาก:** test 20 นัดบอกอะไรไม่ได้ทางสถิติ (ถูก 12/20 ยังเข้ากับการเดาสุ่ม ค่าคลาดเคลื่อนราว +/-11%) และถ้ากรองตามกฎ/ข้ามนัด จะเหลือไม่กี่นัด รายงานต้องเขียนว่าเป็น **proof of concept ของ pipeline** ไม่ใช่หลักฐานว่ามี edge ถ้าโควตาพอควรเพิ่มเป็น 200 นัด
6. **เจ้ามือคนละเจ้าราคาไม่เท่ากัน** ระบุเจ้ามือให้ชัด
7. **ตลาดมีประสิทธิภาพสูง** ผลใกล้เคียงสุ่มเป็นผลที่เกิดขึ้นได้และยอมรับได้ ไม่ใช่ความล้มเหลว
8. **อย่าอ้างข้อมูลจากบทความโปรโมต** (ของ OddsPapi ฯลฯ) เป็นความจริงเด็ดขาด ให้ยืนยันด้วยการเรียก API จริง

## 9. ขั้นตอนถัดไป (ลำดับงาน)

1. สมัครคีย์ OddsPapi แล้วทดลองดึง 3-5 แมตช์ ตรวจว่า response มี: AH เปิด, 1X2 เปิด, เส้นสูงต่ำเปิด, ราคาเสมอ HT, และมีสกอร์ปนมาไหม
2. เลือกลีกเดียวและเจ้ามือ (แนะนำ Pinnacle)
3. เลือกแหล่งผลแข่งสำหรับ label (API-Football / football-data.org / Thscore) และจับคู่กับ fixture ของ OddsPapi ด้วย externalProviders ID หรือชื่อทีม + วันที่
4. เขียนโค้ดแปลง payload เป็นตารางที่มี feature + label ตามหัวข้อ 3-4
5. สร้างโมเดล multi-output และกฎเลือกตลาด/ข้ามนัด
6. รัน walk-forward 80/20 รายงานผลพร้อมช่วงความคลาดเคลื่อน เทียบกับ baseline
7. ถ้าผ่านเกณฑ์ ล็อกโมเดลแล้วเริ่มแผน B
